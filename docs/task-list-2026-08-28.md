### Two hazards found the hard way on 2026-08-29 — both worth a CLAUDE.md rule (Dan's call)

Delegating two tasks to subagents in this shared checkout caused three incidents. Neither hazard is
covered by the existing rules, and both are the *same shape* as rules that already exist.

**1. `git checkout -- <path>` is only safe if you are the only one with edits in that path.**
An agent ran `uv sync`, saw it had modified `pyproject.toml`/`uv.lock`, and reverted them with the
pathspec form — correctly avoiding a whole-tree operation, exactly as rule 1 instructs. It still
destroyed uncommitted work, because those files carried *another session's* edits (the
`trellis-querycache` workspace wiring). **Reverting to HEAD is destructive at any scope.** Rule 1
currently presents `git checkout -- <path>` as the safe alternative to a bare checkout; it is safer,
not safe. The missing half is: check `git status` for the path first, and if someone else's change
is in it, do not revert — ask.

**2. A bare `uv sync` at the workspace root is destructive.** The root is a *virtual* project with
no dependencies, so `uv sync` resolves to "nothing should be installed" and **uninstalls the entire
venv**. An `uv sync` run from a package directory is nearly as bad in a shared checkout: it
re-resolves the shared venv down to that one package's dependencies, which is how `trellis_context`
got uninstalled and another session's `test_context_compile.py` stopped collecting.

The correct form is **`uv sync --all-packages --extra dev`**. Note `--all-extras` does *not* work
here — it pulls `onnxruntime-gpu`, which has no macOS arm64 wheel.

This is the same failure mode as the git rules in a different tool: a command whose name suggests
"make consistent" and whose effect in this layout is "remove", reached for in its short form by
someone who has no reason to suspect it. It belongs next to the git section in the root CLAUDE.md.
**Not added — changing repo conventions is Dan's call**, and a second session independently reached
the same conclusion and also declined to edit it.

**3. The delegation itself was the root cause, and the fix is a partitioning rule.** Both agents were
given disjoint *task* areas, but shared *infrastructure* files (`pyproject.toml`, `uv.lock`, the
venv) are touched by tooling regardless of which source files an agent owns. Agents should own only
files nobody else has modified, and all shared-file wiring should be done by the coordinating session
after they finish.
