secret_scan

Scans HEAD content for committed-credential patterns using a vendored gitleaks ruleset (222 rules, MIT). Reports which ruleset and version produced the result, and its age — a stale ruleset misses formats that did not exist when it was written and returns a confident clean.

Never claims no secrets: only no matches against this ruleset, in the current HEAD snapshot of tracked files. Says nothing about git history, which is where a removed secret still lives.

Why a popover and not the row

That is one of nine, and it is the short half of what secret_scan says about itself. Nine of those on a page is a page nobody reads, and the row needs four facts to be pressable: does it answer anything, when did it last run, what does it cost, and can I run it. The prose is what you open when the four are not enough.

Note what the description is doing in that popover, though: it is the most careful writing in this project. Never claims “no secrets” is a caveat about the answer, and it belongs wherever the answer appears — which is the caveat line under the question, not only here.

And the third case, point 5. The sentence “either a question is missing, or the analysis is evidence for a judgement” is missing the case the owner already ruled on 09-11: an analysis also serves the chat's ad-hoc questions. Not orphaned — the catalog simply cannot say what it serves. Three cases, not two, and the index above carries the third.
